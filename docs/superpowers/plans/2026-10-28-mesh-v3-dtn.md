# Mesh v3 (DTN) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace v2 flooding with DTN-style custody transfer, move the coordinator onto an elected drone, and replace the PyQt GUI with a mission-control web dashboard.

**Architecture:** Pure-logic modules (bundle format, store, routing, election) with no Zenoh, tested with plain asserts; `mesh_node.py` wires them to Zenoh. The dashboard is a stdlib HTTP server that streams a Zenoh snapshot to an offline HTML/SVG page over Server-Sent Events.

**Tech Stack:** Python, Zenoh (`eclipse-zenoh`), ROS 2 launch files (ament_python packages), stdlib `http.server`, vanilla JS + SVG.

**Spec:** `docs/superpowers/specs/2026-10-28-dtn-mesh-design.md`. Hand-off doc: `docs/V3_CHANGES.md`.

## Global Constraints

- Target: Ubuntu 24.04, ROS 2 Jazzy, Gazebo Harmonic, Python 3.12. Code must also run on Python 3.10 (dev machine is 22.04/Humble): no 3.11+ only syntax or stdlib (`tomllib`, `typing.Self`, `except*`).
- No new Python dependencies. Dashboard: no CDN, no external URLs, no JS libraries.
- Shared names, constants, keys and packet format live only in `mesh_common`.
- Simulated radio path unchanged: `mesh/<u>/tx` → `radio_channel` → `mesh/<v>/air` → injector → `mesh/<v>/rx`.
- Nodes never crash on a bad packet (count it, drop it).
- Fake mode (`fake:=true`, no Gazebo) must work for everything; `ros2 run mesh_protocol selftest` is the main proof.
- Branch `v3-dtn`. Each task ends with updating the Status table in `docs/V3_CHANGES.md` and a commit.

1. A bundle for a destination with no route (no `LEADER` yet, node missing from table) → held in the store, never dropped or crashed. Test in Task 2 (`test_no_route_holds`).
2. A lost `CUSTODY_ACK` → sender resends, receiver re-acks the duplicate, the application sees it once. Test in Task 3 (`test_duplicate_reacked_delivered_once`).
3. Store full during a photo transfer → bulk dropped first, commands still accepted. Test in Task 2 (`test_full_store_drops_bulk_first`).

### Task 2: Bundle store and routing (pure logic)

**Files:**
- Create: `src/mesh_protocol/mesh_protocol/store.py`, `src/mesh_protocol/mesh_protocol/routing.py`
- Create: `src/mesh_protocol/test/test_store.py`, `src/mesh_protocol/test/test_routing.py`

**Interfaces:**
- Produces `class BundleStore(limit=STORE_LIMIT)`:
  - `add(pkt, now) -> dict|None`: stores (custody taken); returns the bundle it dropped if full (oldest of the lowest priority present; if the new one is the lowest-priority bundle, it is the one returned).
  - `due(now, next_hop_of, budget) -> list[(pkt, next_hop)]`: up to `budget` bundles whose retry time has come, sorted by `(priority, sent_time)`. `next_hop_of(dst) -> str|None`; `None` → bundle skipped (held). Each returned bundle gets `tries += 1`, `retry_at = now + min(RTO_START * 2**(tries-1), RTO_MAX)`. A bundle whose `tries` reached `MAX_TRIES` for the same next hop resets `tries` to 0 when `next_hop_of` returns a different hop.
  - `ack(bid) -> bool`: removes; True if it was held.
  - `expire(now) -> list[pkt]`: removes and returns expired bundles.
  - `held() -> {0:int, 1:int, 2:int}`; `__len__`.
  - `kick(next_hop)`: sets `retry_at = 0` for bundles waiting on that hop (used when its HELLO returns or routes change).
- Produces `routing.compute_routes(edges, units, relays) -> {unit: {dst: next_hop}}`: `edges` = `{(a,b): quality}` (undirected, up links only); BFS shortest hop count, ties → higher sum of quality; intermediate nodes must be in `relays`.

### Task 3: DTN in `mesh_node.py` (routes from the v2 coordinator process)

**Files:**
- Modify: `src/mesh_protocol/mesh_protocol/mesh_node.py`, `src/mesh_protocol/mesh_protocol/coordinator.py`, `src/mesh_protocol/mesh_protocol/selftest.py`, `src/mesh_protocol/mesh_protocol/tools.py` (`mesh_monitor` columns)
- Create: `src/mesh_protocol/test/test_node_logic.py`

**Interfaces:**
- Consumes: Task 1, Task 2.
- Produces (used by Task 4/5):
  - `MeshNode.handle(pkt, now) -> list[dict]`: pure receive step, returns the bundles to send (custody acks, nothing else); delivery and custody-taking happen inside. `on_rx` = decode + `handle` + send. This split exists so `test_node_logic.py` can drive it without Zenoh (session passed as `None`, publishers stubbed).
  - `MeshNode.routes: dict` (this unit's `{dst: next_hop}`), set from `mesh/coordinator/state["routes"][unit]` in this task (Task 5 replaces the source with `LEADER` bundles).
  - `mesh/stats/<unit>` adds: `held` (dict), `custody_sent`, `custody_acked`, `retransmits`, `expired`, `dropped_full`, `routes`, `leader`, `term`.
  - `mesh/events` items: `{"time","unit","event", ...}` with `event` in `retransmit|expired|custody|route_change|dropped_full|killed|revived` (Task 5 adds `election|leader`, Task 6 `photo`).
  - `mesh/base_b/telemetry` adds `late: bool` (`delay > LATE_AFTER`).
  - Rover publishes `cmd_age_ms` of each applied drive command in its ACK payload; base A includes it in `mesh/base_a/acks`.
  - Coordinator process adds `"routes": compute_routes(edges_from(mesh/links), UNITS, DRONES+["rover"] if relay else [])` to `mesh/coordinator/state`.

Receive rules (spec Part 1 "Custody transfer"): routed bundle with `next_hop != me` → ignore; with `next_hop == me` → always `CUSTODY_ACK` to `path[-1]`, then expired → count + event; duplicate → count; `dst == me` → deliver; else append self to `path`, `ttl-1`, `store.add`. Flooded types keep v2 flood rules, but every drone forwards them regardless of the relay flag. Each loop tick: `store.expire`, then `store.due(now, routes.get-with-neighbour-fallback, budget = SEND_RATE * tick)`, send each with `next_hop` set; `retransmits` counts sends with `tries > 1`. `originate` for routed types puts the bundle in the own store instead of sending directly. Neighbour fallback: `routes.get(dst)` or `dst` if `dst` is a current neighbour, else `None`. HELLO from a neighbour → `store.kick(that neighbour)`.

`failure/control` `{"kill": unit}` / `{"revive": unit}`: the named node stops sending and ignores rx (still publishes stats with `killed: true`).
